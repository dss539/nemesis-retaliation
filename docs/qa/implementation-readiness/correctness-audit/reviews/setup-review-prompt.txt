# Stage 1 blind correctness audit method

## Scope and decision

This audit tests whether the compact base-competitive rules layer is correct enough to support a clean rewrite. It does not revive semantic expansion and does not authorize implementation.

The locked manifest contains exactly 140 audit units:

- all 56 concise rules in `docs/rules/00-foundations.md` through `04-items-and-equipment.md`;
- all 28 FAQ v1.2 units already classified as base-applicable, including the one `base-game-additional-mode` applicability boundary;
- 56 deterministically selected component effects across every preregistered family.

The existing 529 semantic records are comparison/reference evidence only. They remain frozen and withheld from blind derivation.

## Frozen selection

`manifest.json` is generated by `scripts/build_correctness_audit_manifest.py`.

Component candidates are ranked by:

```text
SHA-256(seedMaterial | stratum | sourceIdentity)
```

The lowest required ranks are selected. This prevents outcome-driven cherry-picking. Byte-identical physical copies form one effect candidate; source-different same-title occurrences remain separate candidates. The manifest pins:

- selected identities and source hashes;
- all selection-input hashes;
- all five concise-rule file hashes;
- the frozen semantic artifact hashes;
- exact family counts and pass thresholds.

Changing any input requires a new manifest version and an explicit disposition of the old audit. Do not silently regenerate around an inconvenient selection.

## Audit lanes

### Lane A — blind source packet

For each bounded batch, prepare a packet containing only:

- exact official rulebook/FAQ excerpts and rendered-page locators;
- exact source-bound card/help-sheet pixels or transcriptions;
- authority, version, and base-scope metadata;
- source-local IDs and labels needed to identify the selected unit.

Before derivation, a separate packet-completeness critic checks that all directly relevant cross-cutting official passages, FAQ overrides, visual obligations, and component faces are present. The critic does not see the concise or semantic conclusion.

Source indexes may locate bytes, crops, and versions, but their semantic projections, conclusions, named rule mappings, and conflict dispositions are not included. Legacy implementation files are prohibited.

### Lane B — sealed blind derivation

An isolated reviewer receives only the accepted packet and the closed output contract. It must derive:

- trigger and timing;
- applicability and preconditions;
- actor, decision owner, targets, cardinality, and decline rights;
- public/private/transient/hidden visibility;
- costs and ordered operations;
- finite-supply, impossible-instruction, and partial-resolution behavior;
- exact authority and citations;
- genuine alternatives for every unresolved point, with no default;
- implementation-focused acceptance scenarios.

The final structured answer is persisted and hashed before the reviewer can see downstream material. Hidden reasoning traces are neither requested as evidence nor retained.

### Lane C — reveal and comparison

Only after Lane B is sealed may a comparator inspect:

- the concise rule/FAQ projection under audit;
- relevant frozen semantic records;
- relevant semantic questions and conflicts;
- source-extraction records needed to verify a claimed mismatch.

Classify each downstream claim as:

- `match`;
- `downstream-omission`;
- `downstream-overstatement`;
- `authority-inversion`;
- `hidden-default`;
- `source-ambiguity-preserved`;
- `source-ambiguity-lost`;
- `source-conflict-preserved`;
- `source-conflict-flattened`;
- `transcription-or-packet-gap`;
- `presentation-only`.

A semantic record is not evidence that a blind derivation is correct. Every discrepancy is checked directly against primary source.

### Lane D — independent verification

A different reviewer or model attacks every critical/material discrepancy and a deterministic sample of matches. It receives the source packet, sealed derivation, and proposed comparison disposition. Its findings are advisory until independently verified against cited source bytes.

GLM 5.3 and DeepSeek V4 Pro 0813 may be used as isolated advisors/critics through Ollama Cloud with `think: "max"`. Record the exact tag, provider, request mode, packet hash, prompt hash, final response, and disposition. Do not retain or publish provider reasoning traces. Model review is not human-independent validation.

## Batching

Use bounded packets so every unit remains traceable:

1. five concise-rule files, split into coherent source sections;
2. FAQ units grouped by printed section/page while retaining unit-level results;
3. component effects grouped only when they share a source family and packet.

A reviewer may return several unit results in one call only when:

- every requested unit ID is returned exactly once;
- no result combines evidence across unrelated units;
- returned count equals submitted count;
- packet and prompt hashes are common and recorded;
- failed/omitted units are retried independently rather than inferred.

## Severity and escalation

### Critical

A source-supported discrepancy capable of changing legality, death/survival, victory, secrecy, actor-owned choice, timing of an irreversible effect, authority precedence, finite-supply behavior, or a mandatory no-default boundary.

### Material

A source-supported behavioral discrepancy likely to change state or player options, but not meeting the critical definition.

### Minor

Citation, terminology, or presentation drift that does not change behavior, visibility, timing, ownership, or state.

### Not a defect

A genuine source ambiguity/conflict preserved without a default, a source blocker explicitly retained, or a presentational difference with equivalent behavior.

A **recurring defect pattern** exists when the same root cause produces material-or-worse discrepancies in either:

- at least three audited units; or
- at least two source/component families.

Do not split one root cause into cosmetic labels to avoid escalation.

## Decision threshold

Stage 1 may support rewrite-readiness only after repair and re-verification if it has:

- zero critical errors;
- zero invented authority overrides;
- zero hidden defaults;
- zero recurring defect patterns;
- no unresolved material error in the 56 concise rules or 28 FAQ units;
- at most two isolated material errors in the 56-component sample.

If component errors cluster, expand the affected family. Escalate toward the approximately 339-unit full audit only if defects are systemic. Every correction must be source-linked and tested; changing the audit record is not itself a correction.

## Source-packet completeness safeguard

The Search pilot demonstrated that an omitted cross-cutting passage can manufacture a false ambiguity. Therefore every packet records:

- source files searched;
- exact included locators;
- search terms and neighboring sections checked;
- relevant FAQ/component channels checked;
- known exclusions and why they are irrelevant;
- packet-completeness critic findings and dispositions.

If a later omission is found, preserve the original packet and derivation, add a labeled amendment, and rescore the finding. Never rewrite the sealed baseline.

## Progress and artifacts

- `manifest.json` — immutable selected population and hashes.
- `progress.json` — one status row per manifest unit.
- `audit-result.schema.json` — closed per-unit result contract.
- `packets/` — source-only packets and completeness reviews.
- `blind/` — sealed source-only derivations.
- `comparisons/` — downstream reveals, discrepancies, and direct-source dispositions.
- `reviews/` — adversarial advisor/critic outputs and verified dispositions.
- `reports/` — batch and final decision reports.

`progress.json` may advance only after the referenced result exists and its SHA-256 matches. Never mark an item complete from intent or an unverified model response.

## Required verification

At each checkpoint:

```bash
python3 scripts/build_correctness_audit_manifest.py --check
python3 scripts/validate_correctness_audit.py
python3 scripts/validate_source_extraction.py
python3 scripts/validate_project_status.py
git diff --check
```

Before a final decision, also rerun vocabulary, ontology, semantic reproducibility/adversarial validation, all focused audit tests, and cross-seed deterministic controls. Frozen semantic hashes may change only through a separately reviewed source-correction maintenance event; semantic expansion remains prohibited.

def file_sha256(path: str) -> str:

def rank(stratum: str, candidate_id: str) -> str:
    material = f"{SEED_MATERIAL}|{stratum}|{candidate_id}".encode()
    return hashlib.sha256(material).hexdigest()


def select(
    candidates: Iterable[dict[str, Any]],
    count: int,
    stratum: str,
) -> list[dict[str, Any]]:
    rows = list(candidates)
    ids = [row["sourceIdentity"] for row in rows]
    assert len(ids) == len(set(ids)), f"duplicate candidates in {stratum}"
    assert len(rows) >= count, f"too few candidates in {stratum}"
    ordered = sorted(rows, key=lambda row: (rank(stratum, row["sourceIdentity"]), row["sourceIdentity"]))
    selected = ordered[:count]
    for row in selected:
        row["selection"] = {
            "method": "lowest SHA-256 rank",
            "stratum": stratum,
            "candidateCount": len(rows),
            "score": rank(stratum, row["sourceIdentity"]),
        }
    return selected

    family: str,
    source_identity: str,
    label: str,
    source_path: str,
    source_sha256: str,
    **extra: Any,

        "sourcePath": source_path,
        "sourceSha256": source_sha256,
        "status": "pending-blind-derivation",
    }
    row.update(extra)
    return row


def unique_source_effects(
    rows: Iterable[dict[str, Any]],
    family: str,
    id_field: str,
    label: Callable[[dict[str, Any]], str],
) -> list[dict[str, Any]]:
    grouped: dict[tuple[str, str], list[dict[str, Any]]] = defaultdict(list)
    for row in rows:
        grouped[(row["sourcePath"], row["sourceSha256"])].append(row)
    result = []
    for (source_path, source_sha256), copies in grouped.items():
        representative = min(copies, key=lambda row: row[id_field])
        result.append(
            source_candidate(
                family,
                representative[id_field],
                label(representative),
                source_path,
                source_sha256,
                identicalPhysicalCopies=len(copies),
            )
        )
    return result

class DuplicateKeyError(ValueError):

def strict_pairs(pairs: list[tuple[str, Any]]) -> dict[str, Any]:
    result: dict[str, Any] = {}
    for key, value in pairs:
        if key in result:
            raise DuplicateKeyError(f"duplicate JSON key: {key}")
        result[key] = value
    return result


def strict_load(path: Path) -> Any:
    return json.loads(path.read_text(encoding="utf-8"), object_pairs_hook=strict_pairs)


def sha256_path(path: Path) -> str:
    return hashlib.sha256(path.read_bytes()).hexdigest()


def inside(path: Path, parent: Path) -> bool:
    try:
        path.resolve().relative_to(parent.resolve())
        return True
    except ValueError:
        return False


def add(failures: list[str], condition: bool, message: str) -> None:
    if not condition:
        failures.append(message)


def validate_result_shape(result: dict[str, Any], failures: list[str], label: str) -> None:
    required = {
        "schemaVersion",
        "recordType",
        "auditUnitId",
        "status",
        "blindDerivation",
        "comparison",
        "verification",
    }
    add(failures, set(result) == required, f"{label}: result top-level keys drift")
    add(failures, result.get("schemaVersion") == 1, f"{label}: schemaVersion")
    add(
        failures,
        result.get("recordType") == "stage-1-correctness-audit-unit-result",
        f"{label}: recordType",
    )
    blind = result.get("blindDerivation")
    add(failures, isinstance(blind, dict), f"{label}: blindDerivation missing")
    if isinstance(blind, dict):
        for key in (

            "packetSha256",
            "promptSha256",
            "reviewer",
            "requirements",
            "ambiguities",
            "acceptanceScenarios",
            "packetCompleteness",
        ):
            add(failures, key in blind, f"{label}: blindDerivation missing {key}")
        add(failures, bool(HEX64.match(str(blind.get("packetSha256", "")))), f"{label}: bad packet hash")
        add(failures, bool(HEX64.match(str(blind.get("promptSha256", "")))), f"{label}: bad prompt hash")

            f"{seed}|{selection.get('stratum')}|{row.get('sourceIdentity')}".encode()
        ).hexdigest()

        mapping = manifest.get(section, {})

            continue
        add(failures, isinstance(result_path_value, str), f"result path missing: {unit_id}")
        add(failures, isinstance(result_hash, str) and bool(HEX64.match(result_hash)), f"result hash invalid: {unit_id}")

        add(failures, result_path.is_file(), f"result file missing: {unit_id}")
        if not result_path.is_file():

        add(failures, sha256_path(result_path) == result_hash, f"result hash mismatch: {unit_id}")
        try:
            result = strict_load(result_path)
        except Exception as exc:
            failures.append(f"result parse {unit_id}: {exc}")
            continue
        add(failures, result.get("auditUnitId") == unit_id, f"result ID mismatch: {unit_id}")

    add(failures, declared.get("total") == 140, "progress declared total")
    for status, key in STATUS_COUNT_KEYS.items():
        add(failures, declared.get(key) == status_counts.get(status, 0), f"progress count mismatch: {key}")
    add(failures, schema is not None and schema.get("additionalProperties") is False, "result schema is not closed")

        "passed": not failures,
        "failureCount": len(failures),
        "counts": {
            "manifestUnits": len(units),
            "progressUnits": len(progress_units),
            "statuses": dict(sorted(status_counts.items())),
            "componentFamilies": dict(sorted(families.items())),
        },
        "failures": failures,
    }
