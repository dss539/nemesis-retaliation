# Owner notes — things you should really know (running list)

Kept short. Updated as the autonomous run proceeds. Read this first at the end.

1. **Corpses may be expansion content leaking into base scope.** Two TTS Objective/Mission Task faces (RETRIEVAL, OLD FRIEND) reference "Corpses from the Hibernatorium". No official base-game source mentions corpses; the Gamefound store page lists them only in an add-on pack. Recorded as OQ-013. **RESOLVED:** Owner decided on 2026-09-05 to exclude corpses from base-game scope; RETRIEVAL and OLD FRIEND are formally treated as expansion/add-on content.
2. **Objective "N+" thresholds / "unavailable if you are number 5" have no in-play rule.** Only the setup filter exists (FND-011). Recorded as OQ-014. **RESOLVED:** Documented project interpretation: N+ is a setup filter; "unavailable if you are Character #X" requires the player to choose their alternative Objective.
3. **Overwhelming Fire is a Facility-destruction trigger, not just "game ends".** RB p. 23: running out of Fire markers destroys the Facility (everyone inside dies, INT-010). The corpus previously had no fourth end trigger at all; the draft proposal had also dropped the "Facility is destroyed" clause — corrected at application time. This changes the legacy engine's end-condition set.
4. **Fresh verification after repair produces "unsure", not "pass", for source-variant faces with open semantic questions.** Of the first 144 re-verified repairs: 120 pass, 0 fail, 24 unsure. Every unsure says the same thing: the exact card/room text is now in the corpus, but a SEM-Q (Command nesting, Robot movement, Exploration Noise timing, Item-icon glyph, etc.) leaves its operative meaning unsettled. This is the protocol behaving correctly (open question ≠ pass). **RESOLVED:** Key governing semantic questions (SEM-Q-002, SEM-Q-059, SEM-Q-027, SEM-Q-013, SEM-Q-014, SEM-Q-020, SEM-Q-021, OQ-003) have now been resolved via documented project interpretations based on BGG consensus and developer clarifications.
5. **Burst precondition tightened.** ACT-BURST-001 now requires the adjacent Corridor to contain an Intruder (RB p. 33 "may only Burst at Intruders in an adjacent Corridor"). The old text allowed selecting any adjacent Corridor. Legacy-engine behavior differs.
6. **Independent critics found two real over-reaches, both corrected.** DeepSeek V4 Pro (isolated, max reasoning, read-only) caught (a) the Fire At Will FAQ ruling wrongly co-cited to rulebook p. 33, and (b) my Supply Route "ignore Doors/Intruders" note generalized to all path Objectives when the source prints it for one card. Both fixed in `02c003b`. Its third finding (FAQ `FQ-P03-U07` extending interplay to Action cards/Tactical Gear) was rejected: it is a verbatim official FAQ answer, and FAQ outranks rulebook. GLM 5.3 (same setup) produced no final answer in either run — it spent the whole budget in thinking — but its reasoning tail named two more real defects, both verified and fixed in `0e97617`: an unsourced "loaded" qualifier on Grenade Launcher tokens, and the p. 37 "all Robot effects unavailable" wording standing without p. 23's "effects that only require a Robot still work" exception. Its other candidates (the Nest/Fire FAQ line, "may" on Taser/Duct Tape) checked out as faithful and were left alone.
